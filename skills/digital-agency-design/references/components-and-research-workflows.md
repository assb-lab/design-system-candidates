# コンポーネントと研究Webアプリの設計

必要な画面とユーザーの達成目標から部品を選ぶ。使わない部品は導入しない。

| 研究用画面・操作 | 公式の主な部品 | チェックする状態 |
| --- | --- | --- |
| 実験/プロジェクト一覧 | リソースリスト、検索、テーブル | 検索中、0件、フィルタ、読み込み失敗 |
| 測定条件の入力 | インプットテキスト、セレクト、ラジオ、チェック、説明リスト | 必須、単位、バリデーション、保存と取消 |
| データファイル読み込み | ファイルアップロード／ドロップエリア、プログレス | 種類、サイズ、進捗、中断、再試行、重複 |
| 測定データ表 | テーブル／データテーブル、テーブルコントロール | 単位、ヘッダー、ソート、欠損、横スクロール |
| 解析処理 | ステップナビゲーション、プログレス | 現在位置、処理中、失敗、やり直し |
| 重大通知 | ノティフィケーションバナー、注釈ブロック | 既読、説明、対処方法、支援技術への通知 |
| 削除や重要な変更 | モーダルダイアログ、ボタン | フォーカス制御・復帰、キャンセル |
| 追加情報の開閉 | アコーディオン、ディスクロージャー | 展開状態の通知、キーボード |

## 科学データについての独自追加ルール

- 表には物理量・単位・試料識別子・欠損値と検出限界未満の区別を入れる。
- 単位変換した値には元の単位と処理条件を残す。
- サンプル数や誤差の意味は測定条件から引き継ぐ。デザインのために実験値を改ざんしない。
- グラフ系列色をエラー/成功の状態色と混同しない。グラフの厳密な規則はscientific-editorial等で確認する。
- ファイルの「解析成功」と「ファイル受信成功」を混同しない。非同期処理では状態遷移を明示する。
- 狭幅やキーボード利用時も表や入力の主要操作を失わない。

利用する部品の個別仕様は必ず公式のページ・Storybookで確認する。要約を仕様書の代用にしない。
