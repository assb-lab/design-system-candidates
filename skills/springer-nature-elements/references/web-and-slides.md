# ElementsのWeb/UI設計とスライドへの転用

## Webで重視する構図

- 本文主導の情報階層。見出しはsentence case、意味の分かる見出しを用いる。
- 適切なHTMLセマンティクスを保ち、1ページにh1は1つ、h2→h3の順に構造化する。
- カードは必要な情報を強調する場合だけ使用。カードだらけの研究サイトを避ける。
- 色やフォーカス状態は公式トークン・アクセシビリティ規則を参照。色だけに情報を頼らない。
- データ表に単位、図には軸と出典を付記し、スクリーンリーダーから分かるキャプションを付ける。
- 研究記事ではabstract/summary、main figure、method、references、data availabilityを意味的なまとまりとして設計する。

## 付属HTMLについて

`assets/editorial-starter.html` と `assets/editorial-starter.css` はオリジナルでブランドニュートラルな研究記事テンプレート。**Elements公式CSSを再現するものではない。**

公式Natureテーマを使うときは独自CSSだけを使って公式を名乗るのではなく、正式な `@springernature/elements` パッケージのSCSSを導入し、正しいライセンス・フォント・ロゴ等を別途整備する。

## 学会用スライドでの使い分け

- 情報設計・タイポグラフィ階層は参考にできる。ただしウェブ記事の本文サイズを学会スライドへ直接移植しない。
- 16:9、タイトル28–36pt、本文20–28pt、グラフ軸や注釈は会場で読み取れるサイズから始める。これらは本スキルの**実務上の初期値**でありNatureの公式発表規定ではない。
- FigureのNature投稿規定とは独立し、論文投稿の場合は `nature-figure-style` を使用。
- 論文図版の5–7ptラベルをスライドに引き延ばすのではなく、ラベルを別レイヤーで再生成する。
- PPTXならネイティブ図形・編集可能テキストで再作成する。公式ロゴやブランド専用フォントを無断生成しない。

## 品質チェック

文字サイズ、暗背景と明背景のコントラスト、色覚多様性、カードの過密、グラフの軸・単位、見出し構造、引用の再利用許諾、図表の編集性、印刷と投影の実寸を検証。
